# 总计算预算与运行日志

## 为什么 Phase 2 会长时间不动

Phase 2 的GA会评估多个候选方案；启用机器人完整校验后，候选还要经过IK、碰撞和路径检查。单次机器人序列验证预算与整次装箱预算不同。候选失败、增加托盘数、重新启动GA会累计大量计算时间。以前主要在一整代结束后记录进度，且日志只存在界面内存中，无法准确回查被结束的任务。

本次增加整任务预算和过程可见性，保留原有机器人验证。它不保证在指定时间内一定找到整批可执行解，也不把预算耗尽视为装箱无解。

## 60分钟默认时限

工作台默认总时限为60分钟。点击“装箱设置”，进入“托盘尺寸、算法参数与输出目录…”中的“整次计算总时限”即可修改；基础工作台直接在设置页修改。时限随启动参数传入后台，计算时查看历史不会改变它。

预算覆盖工作台服务的输入、求解与导出检查点，使用单调时钟。到时抛出独立的超时状态，界面显示“已超时（未完成）”，保留当前查看的历史画面。不会将部分计算冒充完成方案。

这是协作停止机制：当前IK求解、模型导入或文件操作可能需要先完成短暂的不可中断段，随后在检查点退出；不会直接强杀Python线程。原子发布过程中超时会回滚已经替换的文件。

## 可以看到哪些进度

- 每个GA新候选开始、结束、累计评估数和耗时。
- 第一阶段正在验证的托盘及箱数。
- 完整机器人验证正在处理的箱号、托盘、动作、接近方向和路径方式。
- IK/路径/预算等具体未通过原因。
- 每5秒更新运行耗时、总时限和最后阶段，即使当前候选还未返回。

“候选通过”仅指该候选或序列的局部验证，不等于整个装箱任务已经完成。只有完成全部检查并成功发布结果，任务才标为完成。

## 每次任务的诊断文件

新运行目录会保留：

- `run.log`：带时间戳的持续日志。
- `run_status.json`：输入文件、托盘、算法与机器人参数、总时限、运行耗时、最后阶段和终止原因。
- 启用机器人完整校验时，另有计算时的工位快照。

运行状态区分 `running`、`completed`、`cancelled`、`timed_out`、`failed`。取消、超时和失败仍保留诊断，但不发布新的完成装箱方案。用户强制结束进程时，文件保留最后一次成功写入的进度，可能仍标为running；此时应结合文件更新时间判断。

运行目录会显示在界面日志中。历史结果列表仍只列出装箱方案，不会把运行状态文件当成方案。

本次控制应用于工作台与`run_packing_job`服务；直接构造求解器的研究代码仍需主动传入协作停止回调。旧任务没有保存这些过程记录，无法补造其实际最后阶段。
