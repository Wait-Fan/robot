# 机器人轻量筛选与完整验证

本次优化适用于 EC66 和 FANUC R-2000iC/210L 的 Windows 离线后端。机械臂显示仍使用原网格，运动学、关节限位、600×800 mm 吸盘包络及暂定 250 mm 工具高度沿用原配置。

## 碰撞计算

从 MuJoCo 导入后的碰撞网格顶点生成保守包围盒。每个关节构型下，先批量检查这些包围盒；确定互不相交的物体对直接排除。包围盒相交时，仍调用原凸网格精细碰撞检查。箱体与箱体使用等价的向量化15轴相交检查，保留原有 0.01 mm 侵入容差。

包围盒用于筛选，不能用包围盒重叠直接判定真实连杆碰撞。此实现自动包住原碰撞模型，避免手工拟合胶囊体过小漏检。没有简化真实连杆长度或放宽采样间距。

IK 成功解使用有界缓存。仅对相同目标位姿、邻近关节分支复用，每次仍检查当前障碍物和携箱碰撞。失败搜索不写入缓存。

## 验证流程

1. 第一阶段生成的固定层块仍完整检查；未通过的块可退回布局搜索。
2. GA 内部先检查装箱几何、开放侧与顺序，再以短预算进行抓取/放置端点 IK 筛选。这仅是候选筛选，不能称为路径通过；短搜索未找到 IK 解时保留“待完整验证”。
3. GA 搜索结束后，按原有紧凑度、异质性排序，每批默认3个候选依次进行完整抓取、抬升、搬运、放置、撤离验证。一批失败后继续下一批，找到通过方案才接受。
4. 最终整批仍需完整路径审核。只有通过审核的结果才写入成功文件并开放机械臂轨迹回放。

相同场景、相同已放箱前缀及相同起始关节状态下，复用已完成六段动作的箱子轨迹。修改箱体位置、姿态、顺序、工位、工具、开放侧或采样参数会使对应缓存失效。复用时恢复已放障碍物和关节状态。缓存仅存在于本次计算进程，不跨程序重启恢复。

## 设置位置与超时含义

打开 **工位布局 → 验证与计算**，可以调整：

- 每箱验证上限：默认30秒，每放一箱重新计时。
- 每段路径上限：沿用场景中的2或3秒，可调整。
- 详细验证批次：默认3个。
- GA分层验证：默认开启，可以关闭以对照旧的每候选完整验证方式。

旧场景中的 `sequence_budget_seconds` 作为每箱预算的兼容默认值；新字段为 `box_budget_seconds`，优先级更高。用户保存的工位文件不会被自动覆盖。整次任务仍受装箱设置中的总时限约束，默认60分钟。

单箱验证预算耗尽时，以“超时，未完成”结束当前任务，保留日志；不会把整盘作为不可行直接退回 GA，也不会把部分轨迹发布为成功结果。路径搜索失败仅表示该次搜索没有找到路径，不等于已证明无解。

## 有界验证结果（2026-11-25）

同一现场 FANUC 场景、同一个历史布局首箱（530×350×480 mm）、相同开放侧及完整路径采样设置：原版4.88秒，优化版1.41秒，约快3.5倍。这是单箱实测，不代表全部数据集有相同加速比例。

10箱测试：原版约30秒后因整序列预算结束，完成5箱；优化版约8.97秒完成8箱，在第9箱未找到IK或路径，状态仍是未验证。该结果说明超时误判和验证成本得到改善，不能据此声称整盘已可执行。

当前仍是离线、离散采样验证；不包含真机标定、吸附承载、负载动力学与控制器执行认证。
