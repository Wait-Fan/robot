# 多个开放侧与侧向直线优先

在2025工作台点击“设置”，勾选允许的方向后确认。默认仅勾选 +Z；需要侧向放置时，请勾选实际开放的 X/Y 侧。

- `+Z`：从目标上方接近。
- `+X/-X/+Y/-Y`：从相应托盘侧向目标接近。X沿托盘长边，Y沿短边；与屏幕视角无关。
- 至少保留一项；未勾选的方向不会被用于回退。+Z可作为侧向失败后的备用方向。
- 每个箱子可以采用不同方向。修改后需重新计算，历史轨迹不直接改写。当前方向选择在本次会话内有效。

工作台和CLI默认采用 `side_direct_first`：

1. 在无箱体遮挡的已选X/Y方向中，按当前TCP到侧向入口的直线距离排序，先尝试各方向的笛卡尔直线搬运。
2. 搬运至托盘外的侧向接近点，再沿该侧方向直线插入目标，释放后直线撤离。接近点保证携箱整体位于托盘边界之外，另加所设接近间距；机器人、吸盘和携箱仍需要全段碰撞验证。
3. 各侧直线均未验证通过时，再尝试侧向RRT-Connect搬运；这些方向仍不通时，尝试已勾选的+Z。

没有强制经过整个托盘堆垛上方的安全点。抓取后仍保留离开取箱台的短距离抬升。所谓侧向直线由“到侧向接近点的直线搬运”和“沿所选侧的直线插入”组成，并不声称取箱到放箱整段共用一条直线。

先在“工位布局”配置机械臂、托盘、取箱台和障碍物并应用，勾选“机器人完整校验”，才能计算实际IK、夹具/连杆/携箱碰撞和轨迹。未启用时只给出箱体几何候选方向，不能据此认定机器人直线路径已经通过。

界面结果分别统计侧向、上方及实际侧向直线箱数。几何结果明确标为“几何候选”；完整校验结果标为“已验证”。JSON中：

- `robot_diagnostics.direction_selection_policy`：方向策略。
- `robot_diagnostics.checks[].open_direction`：候选方向；完整验证后同步为实际方向。
- `motion_verification.directions_by_box[]`：实际方向、`transfer_mode`、侧向入口TCP位姿与各次尝试的失败原因。
- `transfer_mode` 为 `cartesian_direct` 或 `joint_rrt`；各轨迹段另记录 `path_mode` 和目标TCP。

多方向顺序搜索允许有限回溯；失败方向重试前恢复关节、携箱、障碍物和轨迹状态。先里后外规则与允许进入的侧面独立，已放箱体保持固定。

CLI示例：

```powershell
python main.py --algorithm robot2025 --input-json boxes.json --open-direction=+Z --open-direction=-X --open-direction=+Y --robot-scene configs/workcell.json --no-show
```

为保持已有程序调用兼容，`ApproachConfig`直接构造的默认策略仍是 `first_feasible`；工作台和CLI显式使用新策略。CLI可用 `--direction-policy first_feasible` 比较旧策略。

所有路径检查仍受IK、路径和整批计算预算限制，采用离散碰撞采样。未找到路径按未验证处理，不等于证明无解，也不代表实机已验证。
