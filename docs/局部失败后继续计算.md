# 局部路径失败后继续计算

此前某箱局部重试耗尽会立即结束整次任务，造成“前39箱通过，第40箱搬运未完成，整批直接停止”。现在将局部未完成与全局停止分开处理。

第一阶段某箱路径暂未完成时，只提取已经完整通过“接近取箱、抓取、抬升、搬运、放置、撤离”六阶段的连续前缀。程序重新检查这个前缀的严格顺序、几何、支撑、稳定性和机器人验证结果；可复用同场景的完整正缓存。通过后将其保留为独立托盘并封存，仅失败箱及后续尾部作为余箱继续安排，同时继续检查其余托盘。

例如48箱中第40箱失败，如果前39箱的前缀复核通过，则保留39箱，剩余9箱另行布局。不会把失败箱或未完成阶段计入已装数量；保留的前缀也不会被后来填箱修改。封存部分托盘可能增加托盘数量，这是优先获得完整可执行结果的取舍。

GA完整路径验证遇到未完成候选时，标记为 `motion_pending`，继续尝试其他排名候选；它不等于几何不可行，也不能作为最终结果发布。候选都用尽仍没有完整可执行方案时，才显示“机器人规划未完成”，并保存相应诊断。确实违反几何硬约束的候选仍可触发增加托盘数继续搜索。

单箱预算耗尽可由上述局部流程处理；总任务时限和用户取消始终有效。不能保留不满足几何、支撑、稳定性或机器人验证的前缀。最终仍要求箱数守恒、全部箱体装运、严格顺序和完整机器人路径检查通过，不发布假成功。

余箱托盘数估算不再计入已封存托盘的剩余容量，避免尝试实际上无法填入的盘数。日志分别记录恢复前缀、延期尾箱、路径待验证候选和最终候选用尽。

更新需要重启程序。旧任务的检查点保留供诊断，但本次没有新增跨进程自动续跑功能；新计算在同一次运行内复用已验证缓存。本次仅做确定性、界面及缓存回归，没有启动新的668箱生产搜索或真实模型整批路径试算。
