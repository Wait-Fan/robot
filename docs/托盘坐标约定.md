# 托盘长边 X 坐标约定

新计算统一使用：X沿托盘较长底边，Y沿较短底边，Z竖直向上。原点是装箱底面的一角，X、Y从原点指向托盘内部。正方形托盘两条底边相等，保留原定义。

例如，输入的托盘底边为1440、2240，限高720，计算及显示会统一为X=2240、Y=1440、Z限高=720。JSON/Excel文件里的两条底边不必先手动调换；程序在导入到工作台及开始计算时自动处理，原始数据文件不修改。手动输入底边尺寸反了，也会在确认设置时自动交换。

只规范托盘坐标，箱子的原始长宽和允许姿态保持不变。界面和命令行使用相同规则；命令行的`--pallet`依然覆盖输入尺寸，然后按长边X归一化。

接近方向中的`+X`表示从长边的X正端向目标靠近，实际接近运动朝X减小方向；`-X`表示从另一端接近。`+Y/-Y`对应短边的两端，`+Z`表示从上方往下。

结果JSON的`coordinate_system`记录坐标约定，`pallet.length`是X长度、`pallet.width`是Y长度。坐标CSV与计算结果、三维图保持一致。以前生成的结果按原坐标读取和显示，不会只交换托盘尺寸而改变已有布局；需要重新计算才能应用新规则。

## EC66场景标定

`base_T_pallet`必须明确对应哪个托盘坐标系。场景可设置：

- `"pallet_frame_convention": "input_length_width"`：默认值，兼容已有配置。原X对应输入length，原Y对应输入width。当width更大时，程序以X新=+Y原、Y新=-X原、原点新=(length原,0,0)进行右手系转换，并把新坐标接入既有机器人标定；实际托盘矩形仍位于原位置。
- `"pallet_frame_convention": "long_side_x"`：标定本身已经采用长边X。程序直接使用`base_T_pallet`。

位姿矩阵平移单位是米，尺寸转换倍率继续使用`length_scale_to_m`。取箱TCP、机器人初始构型和基座坐标系中的固定障碍保持原定义。转换矩阵记录在`robot_diagnostics.motion_verification.pallet_frame_mapping`中，并纳入模型参数指纹。

上述处理用于软件离线模型，不替代实际工位的标定。
